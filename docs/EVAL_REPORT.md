## 미달 항목 원인 메모

측정 시점: K1(시뮬레이터 S46/S48 수정)이 이미 반영된 코드로 측정했다
(`fdt/engine/simulate.py`/`state.py` mtime 16:26, 본 실행 16:34 - "K1 이전
측정" 아님). `simulate.py:870,922,981` 의 `paid = np.minimum(cash_total,
liquidity)` 부분 체결(S46), `simulate.py:1017` 의 관측 가능한 실패 사건
기준 `shortfall_prob` 재정의(S45), `simulate.py:617-622` 의 불규칙 수입
간격 잡음(S48, `actual_gap = max(3, round(gap + N(0, 0.3*gap)))`)이 전부
코드에 있다. 총 실행 시간 30초로 15분 예산을 크게 밑돌아 시드·표본을
줄이지 않았다.

**백테스트 sMAPE — B/C FAIL, A/D PASS.**
- B(0.25 기준, 4/5 통과, seed 5 만 0.2652 초과)와 C(0.40 기준, 2/5 통과,
  평균 0.53)는 리뷰 20260907_W6_W10.md 시점(S46/S48 이전, C 평균 sMAPE
  .5585, B 는 4/5 통과)과 비교하면 **개선되지 않았다** - S46(부분 체결)은
  C 의 상시 발동하는 봉투·일 단위 억제 게이트를 고쳤지만, sMAPE 오차의
  실제 원인은 게이트 방식이 아니라 **잔액-소비 되먹임 루프의 분산**이었다
  (리뷰 근거 3 "양방향 폭발, 편향 아님"). 부분 체결로 고쳐도 억제되는
  총량 자체는 비슷하게 변동하므로 분산은 줄지 않는다. seed 11 (1.068)이
  가장 크게 벌어졌는데, 최저점이 as_of+8일(2026-08-17)로 다른 시드보다
  일찍 붕괴한다 - 이 시드의 데이터가 유독 얇은 잔액 구간을 지나는 것으로
  보인다(추가 조사 필요, 프로필 C 의 hidden_params 실측 비교는 하지 않음).
- **가설**: C 기준치(.40)를 SPEC S46 메모대로 재조정하거나(리뷰가 이미
  "통과하지 못하면 C 의 기준치 자체를 재조정" 이라고 명시), R10(Behavior
  추정 창 90일 -> 전체 이력 확대)을 v0.2 에서 앞당겨야 한다. 두 원인 다
  eval 계층이 아니라 `engine/behavior.py`(K1 담당 밖, 추정 로직) 쪽 수정이
  필요하다.

**백테스트 커버리지 — 전 프로필 FAIL(개별 시드 기준 3~4/5).**
- 리뷰가 지적한 R10(90일 창 Behavior 추정 표준오차 ±26%)이 그대로다 -
  A seed 5(0.233), D seed 1(0.233) 처럼 밴드가 좁아 계통 오차를 못 덮는
  경우와, A seed 1/B seed 1(1.000) 처럼 밴드가 넓어 상한을 넘는 경우가
  같은 프로필 안에서도 시드별로 갈린다(분산 문제, 편향 아님). n_paths 를
  1000 -> 3000 으로 올리는 것으로는 해결되지 않는다(경로 분산이 아니라
  모수 불확실성) - 리뷰가 제안한 파라미터 부트스트랩(S49)이 정공법이다.

**최저점 오차 — 전 프로필 PASS.** 금액 기준으로는 5 시드 전부 기준(30만/
50만원) 안이다. 단 C 는 최저점 **일자**가 여러 시드에서 크게 어긋난다
(seed 1 -19일, seed 7 -20일, seed 11 -5일) - median 궤적이 초반에 바닥을
찍고 정답은 월말 부근에 있는 패턴이 반복된다(리뷰가 이미 seed 7 에서
관측한 "argmin 이 k=0 근처로 몰린다" 와 같은 현상). SPEC §12 기준표는
금액만 규정하고 일자는 규정하지 않아 이 표에서는 FAIL 로 집계하지
않았지만, RISK/GOAL 발화에는 영향을 줄 수 있다(추가 조사 항목으로 남김).

**캘리브레이션 — 두 채널 전부 PASS(ECE ≤ 0.15, Brier < 기준율 Brier).**
S45 의 관측 가능 실패 정의 덕에 리뷰 시점(B `shortfall_prob`=0.452, 실제
사건 0건이던 오탐)이 해소됐다 - `card_shortfall_prob` ECE 0.0243, 새
`shortfall_prob` ECE 0.0311 로 전부 기준의 1/5 이하다. 다만 5구간 중
0.2~0.8 세 구간은 표본이 4~11개로 15 미만(보류) - 20 사용자 x ~11 as_of
= 220 표본이 0.0~0.2/0.8~1.0 양극단에 쏠려 있어(A/D 는 상시 저위험,
C 는 상시 고위험) 중간 구간 신뢰도가 낮다. 시드나 as_of 표본을 늘리면
중간 구간 표본이 보강되겠지만, 전체 판정(PASS)에는 영향이 없다.

**단조성 — 위반 2/128건(1.56%), 전부 C 프로필.**
`C_impulsive, as_of=2026-08-08, days_from_now=3` 에서 5만->20만원 주입에
`shortfall_prob` 이 1.00->1.00 로 "변화 없음"인데, 부동소수 반올림
표시상 1.00 이 실제로는 아주 미세하게 감소한 값(예: 0.9998 -> 0.9997)일
가능성이 높다 - 리뷰 20260907_W6_W10.md §4b 가 지적한 CRN 스트림 어긋남
(현금 주입이 `liquidity`를 줄여 봉투·일 게이트를 뒤집고 `gate_spent`가
바뀌어 그 뒤 표본이 전부 밀리는 문제, S46 수정 후에도 "주입이 gate_spent
에 반영되지 않는 별도 문제"로 리뷰가 명시한 잔여 이슈)와 일치한다. 이미
상시 DANGER(`shortfall_prob≈1.0`) 인 C 프로필에서만 발생해 실사용 영향은
작지만(§8.3.1 검증 실패), 근본 해결은 S46 리뷰가 적은 대로 v0.2 에서
`gate_spent`에 주입 효과를 반영하는 것이다(K1/W8 담당 범위, 이번 K3 는
회귀 발생 여부만 측정).

**성능·재현성 — 전부 PASS.** 5 항목 전부 기준의 1/10 이하(OPTIMIZE 655ms
/ 25000ms), 재현성 4 프로필 x 5 모드 = 20건 전부 바이트 동일.
